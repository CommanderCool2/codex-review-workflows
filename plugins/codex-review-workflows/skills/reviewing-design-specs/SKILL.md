# Reviewing Design Specifications

Treat the full session as source material. Build a checklist of adopted decisions and requirements, including user-provided GitHub issues, links, pasted or copied files, and retrieved artifacts. Separate adopted decisions from options merely discussed; later explicit user decisions supersede earlier ones.

Compare the completed spec against that checklist. Fix omissions, contradictions, ambiguity, and incoherence directly in the spec without changing its intent. If referenced input is missing from context, retrieve it when possible; otherwise identify the gap. If sources conflict and the session did not resolve them, leave the affected text unchanged and ask the user.

After editing, reread the spec against the checklist, then report material fixes and unresolved conflicts.
